## 1. LICENSE — choose before first commit **[USER DECISION]**

No software license is declared. Without one, the default is "all rights
reserved" — meaning nobody can legally copy, modify, or distribute the code
even if it's on a public GitHub repo. Adding a `LICENSE` file before the
first commit means the license is part of the initial history.

### Recommended options

| License | One-line summary | Fits if… |
| --- | --- | --- |
| **MIT** | Permissive, attribution required, no copyleft | You want maximum adoption and minimal friction |
| **Apache-2.0** | Permissive + explicit patent grant + NOTICE file | You want patent protection and enterprise-friendliness |
| **BSD-2-Clause** | Permissive, attribution required, very short | You want MIT-like terms in fewer words |
| **BSD-3-Clause** | Permissive + no-endorsement clause | You want MIT + name protection |
| **GPL-3.0** | Copyleft — derivatives must also be GPL | You want to require open-source derivatives |
| **Unlicense** | Public domain dedication | You want to waive all rights |

### How to add (after choosing)

```bash
# Option A — use GitHub's license templates (requires gh CLI or web UI):
gh repo create davidnichols-ops/parallax --public --license mit

# Option B — add the file locally before first commit:
# Download the license text from https://spdx.org/licenses/ or
# https://choosealicense.com/ and save as LICENSE in the project root.
# Then add a line to README.md under the title:
#   "Licensed under the MIT License — see [LICENSE](LICENSE)."
```

### Fan-project note

`docs/licensing-and-attribution.md` covers the *Star Trek* inspiration
provenance and fan-project disclaimer. It is **not** a software license — it
does not grant rights to the code. The `LICENSE` file is the software
license; `licensing-and-attribution.md` is the asset/content provenance
document. Both are needed and serve different purposes.

## 4. Release tag and artifact upload **[USER ACTION]**

The CI workflow (`.github/workflows/ci.yml`) automatically builds a release
DMG + SBOM when a `v*` tag is pushed. The artifacts are uploaded as GitHub
Actions artifacts (not GitHub Releases). To create a proper GitHub Release:

### Step 1 — tag the release

```bash
git tag -a v2.1.0-rc5 -m "Release candidate 2.1.0-rc5"
git push origin v2.1.0-rc5
```

### Step 2 — wait for CI

The `release` job in `ci.yml` triggers on `refs/tags/v*`. It builds the DMG,
generates the SBOM, and uploads them as Actions artifacts. Monitor at:
`https://github.com/davidnichols-ops/parallax/actions`

### Step 3 — create a GitHub Release from the tag

```bash
# Option A — gh CLI:
gh release create v2.1.0-rc5 \
    --title "Parallax 2.1.0-rc5" \
    --notes-file docs/release-notes-rc5.md \
    --prerelease

# Option B — Web UI:
# Go to https://github.com/davidnichols-ops/parallax/releases/new?tag=v2.1.0-rc5
# Mark as "Pre-release" (rc = release candidate)
# Attach the DMG and SBOM downloaded from the Actions artifacts
```

### Step 4 — attach the DMG and SBOM to the release

The CI workflow uploads artifacts to Actions, not to Releases. To attach
them to the GitHub Release:

```bash
# Download the artifacts from the CI run
gh run download <run-id> -n Parallax-2.1.0-rc5-dmg
gh run download <run-id> -n Parallax-2.1.0-rc5-sbom

# Attach to the release
gh release upload v2.1.0-rc5 \
    Parallax-2.1.0-rc5.dmg \
    parallax-sbom.json
```

Alternatively, build locally and upload directly (bypasses CI):

```bash
./Scripts/build-release.sh --version 2.1.0-rc5 --output ./dist
./Scripts/generate-sbom.sh --version 2.1.0-rc5 --output ./dist/parallax-sbom.json
gh release upload v2.1.0-rc5 \
    dist/Parallax-2.1.0-rc5.dmg \
    dist/parallax-sbom.json
```

## 5. Secrets and log exclusion verification **[USER ACTION — before push]**

Before the first push, verify that no secrets or transient files are staged:

```bash
# 1. Verify .gitignore is working — these should all be empty:
git ls-files --cached | grep -E '^(\.build|dist|logs|Scripts/AppIcon\.iconset)/'   # expect empty
git ls-files --cached | grep -E '\.DS_Store$|\.backup-'                             # expect empty

# 2. Scan staged content for common secret patterns:
git ls-files --cached -z | xargs -0 grep -IlE 'ghp_[A-Za-z0-9]{36}|sk-[A-Za-z0-9]{20,}|AKIA[0-9A-Z]{16}|-----BEGIN (RSA |EC )?PRIVATE KEY-----' 2>/dev/null   # expect empty

# 3. Verify the stray MAOS log is not staged:
git ls-files --cached | grep 'logs/'   # expect empty

# 4. Check for any large files that shouldn't be in a source repo:
git ls-files --cached | xargs -I{} du -h {} 2>/dev/null | sort -rh | head -10
# AppIcon.icns (~1.3MB) and AppIcon.appiconset PNGs (~1.3MB total) are
# expected — they are the source-of-truth app icon. No other large files
# should appear.
```
